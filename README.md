# 💻 Descripción del proyecto

</summary>

**UNL SmartChair** es una plataforma web desarrollada para modernizar y centralizar la gestión de eventos académicos de la **Universidad Nacional de Loja**.

El sistema está inspirado en **EasyChair**, pero ha sido diseñado pensando en las necesidades de las instituciones de educación superior, ofreciendo una experiencia moderna, intuitiva y adaptable a futuros requerimientos.

## 🎯 Centraliza procesos como

- 📅 Gestión de congresos y eventos académicos.
- 📄 Envío de artículos científicos.
- 🧑‍⚖️ Revisión por pares bajo modalidad de doble ciego.
- 💳 Gestión de pagos e inscripciones.
- 📜 Generación automática de certificados.
- 📊 Panel administrativo con estadísticas en tiempo real.

## 🚀 Principales ventajas

- Interfaz moderna e intuitiva.
- Arquitectura cliente-servidor basada en API REST.
- Diseño modular y escalable.
- Integración sencilla con otros sistemas institucionales.
- Preparado para futuras aplicaciones móviles.
- Adaptable a múltiples eventos académicos.

</details>

# 🚀 Instalación y ejecución local

</summary>

## 📋 Requisitos previos

Antes de comenzar, instala las siguientes herramientas en tu equipo.

| Herramienta | Versión recomendada | Descarga |
|:-----------|:-------------------:|:---------|
| 🐍 Python | 3.11 o superior | https://www.python.org/downloads/ |
| 🟢 Node.js | 18 LTS o superior | https://nodejs.org |
| 🗄️ MariaDB | 10.11 o superior | https://mariadb.org/download/ |
| 🐙 Git | Última versión | https://git-scm.com/downloads/ |

> [!IMPORTANT]
>
> Durante la instalación de **Python** en Windows recuerda marcar la opción:
>
> ✅ **Add Python to PATH**

---

# 📥 Paso 1. Clonar el repositorio

```bash
git clone https://github.com/YooneR1209/SmartChair.git

cd SmartChair

git checkout develop
```

---

# 🗄️ Paso 2. Configurar MariaDB

Una vez instalado MariaDB, crea una base de datos para el proyecto.

```sql
CREATE DATABASE smartchair_db CHARACTER SET utf8mb4;
```

> [!NOTE]
>
> El repositorio incluye los archivos:
>
> - `mariadb_init.bat`
> - `mariadb_init.ps1`
>
> Estos fueron creados para un entorno específico de desarrollo.
>
> **No se recomienda ejecutarlos**, ya que modifican configuraciones locales de MariaDB.

---

# ⚙️ Paso 3. Configurar el Backend

Ingresar al backend

```bash
cd backend
```

---

## Crear un entorno virtual

```bash
python -m venv .venv
```

---

## Activar el entorno virtual

### Windows

```bash
.venv\Scripts\activate
```

### Linux / macOS

```bash
source .venv/bin/activate
```

---

## Instalar dependencias

```bash
pip install -r requirements.txt
```

> [!TIP]
>
> Si `requirements.txt` no estuviera disponible, puedes instalar manualmente las dependencias principales:
>
> ```bash
> pip install django djangorestframework djangorestframework-simplejwt django-cors-headers python-dotenv mysqlclient stripe
> ```

---

## Problemas con mysqlclient (Windows)

Algunas instalaciones de Windows presentan errores al compilar `mysqlclient`.

Como alternativa puedes ejecutar:

```bash
pip install pymysql
```

El proyecto contempla este driver como reemplazo.

---

# ⚙️ Paso 4. Configurar las variables de entorno

Copiar el archivo de ejemplo.

### Windows

```bash
copy .env.example .env
```

### Linux / macOS

```bash
cp .env.example .env
```

Editar el archivo `.env`.

Configuración mínima recomendada:

```env
SECRET_KEY=una-clave-segura

DEBUG=True

ALLOWED_HOSTS=localhost,127.0.0.1

DB_NAME=smartchair_db

DB_USER=root

DB_PASSWORD=tu_password

DB_HOST=localhost

DB_PORT=3306

FRONTEND_URL=http://localhost:5173
```

También es posible utilizar una cadena de conexión:

```env
DATABASE_URL=mysql://usuario:password@localhost:3306/smartchair_db
```

O configurar individualmente:

- MARIADB_HOST
- MARIADB_PORT
- MARIADB_DATABASE
- MARIADB_USER
- MARIADB_PASSWORD

> [!NOTE]
>
> Las variables relacionadas con **Stripe** o **correo electrónico** pueden dejarse vacías durante el desarrollo local.

---

# 🛠️ Paso 5. Preparar la base de datos

Aplicar las migraciones.

```bash
python manage.py migrate
```

Crear un usuario administrador.

```bash
python manage.py createsuperuser
```

---

# ▶️ Paso 6. Ejecutar el Backend

```bash
python manage.py runserver
```

El servidor estará disponible en:

```
http://localhost:8000
```

---

# 🎨 Paso 7. Configurar el Frontend

Abrir una **nueva terminal**.

Ingresar a la carpeta del frontend.

```bash
cd frontend
```

Instalar dependencias.

```bash
npm install
```

Ejecutar el proyecto.

```bash
npm run dev
```

Por defecto Vite utilizará el proxy hacia:

```
http://localhost:8000
```

Si el backend utiliza otra dirección, configura:

```env
VITE_API_URL=http://tu-backend
```

# ❓ Problemas comunes

</summary>

## 🔴 Error al conectar con MariaDB

Verifica que el servicio esté iniciado.

### Windows

```bash
net start MariaDB
```

### Linux

```bash
sudo systemctl start mariadb
```

Comprueba además:

- La contraseña definida en `.env`.
- Que la base de datos `smartchair_db` exista.
- Que el puerto sea el **3306**.

---

## 🔴 ModuleNotFoundError

Generalmente ocurre porque el entorno virtual no está activo.

Linux

```bash
source .venv/bin/activate
```

Windows

```bash
.venv\Scripts\activate
```

---

## 🔴 Error instalando mysqlclient

En Windows ejecuta:

```bash
pip install pymysql
```

---

## 🔴 Error ejecutando npm

Comprueba la versión instalada.

```bash
node -v
```

Debe ser **18** o superior.

---

## 🔴 Puerto ocupado

Backend

```
8000
```

Frontend

```
5173
```

Finaliza el proceso que esté utilizando esos puertos o cambia el puerto de ejecución.

---

## 🔴 Error con las migraciones

Si aparecen errores relacionados con la base de datos:

```bash
python manage.py makemigrations

python manage.py migrate
```

---

## 🔴 No puedo acceder al panel de administración

Asegúrate de haber creado un superusuario.

```bash
python manage.py createsuperuser
```

Luego accede a:

```
http://localhost:8000/admin
```

# 🎯 Objetivo del sistema

</summary>

El propósito de **UNL SmartChair** es ofrecer una solución tecnológica que permita gestionar de manera eficiente todas las etapas involucradas en la organización de eventos académicos, desde la creación del congreso hasta la emisión de certificados para los participantes.

La plataforma busca reducir procesos manuales, centralizar la información y facilitar la interacción entre autores, revisores, organizadores y administradores.

## Objetivos específicos

- 📅 Centralizar la administración de eventos académicos.
- 📄 Gestionar el envío y seguimiento de artículos científicos.
- 🧑‍⚖️ Automatizar el proceso de revisión por pares.
- 💳 Facilitar el registro de participantes y la gestión de pagos.
- 📜 Generar certificados digitales automáticamente.
- 📊 Proporcionar estadísticas para la toma de decisiones.
- 🔒 Garantizar seguridad mediante autenticación y control de roles.
- 🌎 Diseñar una plataforma escalable para futuras integraciones institucionales.

> [!NOTE]
>
> SmartChair ha sido diseñado para adaptarse a diferentes tipos de eventos académicos, permitiendo su crecimiento conforme evolucionen las necesidades de la institución.

</details>

# 🏗️ Arquitectura del sistema

</summary>

La plataforma implementa una arquitectura **Cliente - Servidor**, donde el frontend desarrollado en **React** consume una **API REST** implementada en **Django REST Framework**.

<div align="center">

<img src="https://github.com/YooneR1209/SmartChair/blob/main/images/ChatGPT%20Image%2016%20abr%202026%2C%2019_53_59.png" width="550">

</div>

---

## Flujo general

```text
            Usuario
               │
               ▼
        React + Vite
               │
       Solicitudes HTTP
               │
               ▼
    Django REST Framework
               │
               ▼
          MariaDB
```

---

## Características

- Arquitectura Cliente - Servidor.
- API REST basada en JSON.
- Separación entre frontend y backend.
- Diseño modular.
- Fácil mantenimiento.
- Escalable para futuras aplicaciones móviles.
- Preparada para integrar servicios externos.

---

## Beneficios

| API REST | Comunicación estandarizada |
| React | Interfaces dinámicas |
| Django | Seguridad y productividad |
| MariaDB | Persistencia de datos |
| Arquitectura modular | Escalabilidad |
